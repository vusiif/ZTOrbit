# 桌面共享客户端插件

## 功能简要说明

`desktop-share` 客户端插件（版本 `0.1.0`，客户端 API `0.5`）在客户端“共享”菜单中提供桌面共享页面：共享者连接服务端，选择一块屏幕或一个窗口发起共享，并查看房号与观看人数；观看者连接同一服务端，输入八位房号加入观看。

- 服务器地址支持 `host[:port]`，默认端口 `18100`。只有点击“连接”才建立连接；打开页面、刷新来源、填写地址或房号都不会联网或开始采集。
- 来源只列出屏幕和窗口；开始共享前必须已连接并选择有效来源。
- 默认视频格式为 H.264，提供 `720p30`（约 2 Mbps）和 `1080p30`（约 4 Mbps）两档；“文字桌面 · 变化块”为可选无损模式。画面保持原始宽高比，多余区域填黑。
- 共享者只向服务端上传一份画面，由服务端转发给同一房间的观看者；同一房间最多八名观看者，观看者不能发布画面或控制共享者桌面。
- 共享与观看互斥，同一客户端同时只共享一个房间或观看一个房间。开始、加入、停止、退出和取消都由用户显式触发，过渡操作有明确状态和取消入口。
- 静态桌面是正常内容：长时间没有新画面时显示等待或中断提示，不自动换源。来源关闭、屏幕移除、媒体故障、服务端关房或连接断开都会给出明确结果，用户可以重新操作。
- 菜单切换、隐藏或最小化保留已经建立的会话；完全退出程序、卸载插件或点击停止时结束共享并释放采集。停止失败会显示原因并保留重试入口。
- 只保存服务器地址和视频档位，不保存房号、token 或自动共享状态。首次打开时地址为空，需要用户显式填写并连接。
- 连接失败、建房／入房失败和媒体错误显示原因与下一步；不自动重连、不自动重新采集、不自动切换来源或档位。

使用条件：

- Windows x64 客户端，安装 `z2_desktop_share-v0.1.0.z2plugin` 与媒体工作进程 `z2_media_worker-v2.0.0.z2plugin`。插件依赖 `media >=2.0.0 <3.0.0` 的 `media.session / 1`。
- 目标服务端运行 Java 25 宿主和同版本 `desktop-share` [服务端插件](../../server/docs/desktop-share.md)（服务端 API `0.2`），客户端使用其 TCP 控制端口和 UDP 媒体端口。
- 房号只在生成它的服务端有效；服务入口应限制在 ZeroTier 或可信内网。
- 首期只共享画面，不共享麦克风或系统声音，不提供远程键鼠、文件传输、录制、账户、房间密码、入房审批或客户端直传。

## 当前遗留问题

客户端插件文件名为 `z2_desktop_share-v0.1.0.z2plugin`，配套媒体包为 `z2_media_worker-v2.0.0.z2plugin`。本次产物更名不表示以下功能限制已解决。

### 正式包

- **阶段七仍未关闭。** 正式包的停止证明与包绑定（P2）已有通过结论，但 P3 的 RSS、真实环境覆盖和测试证据缺口未全部通过；相关限制没有明确接受记录，不能因为整理文档写成已解决。
- **长时内存仍有未定位项。** 三十分钟正式包测试在稳定窗口内的客户端 RSS 有界，但此前出现过的约 +10.72 MiB 残余阶跃没有被独立复现，分配点也没有定位。不能把“窗口内有界”称为无泄漏或长期稳定。
- **原生真实环境未验证。** 原生每显示器高 DPI、多屏拔插、锁屏／安全桌面、真实权限拒绝、真实复杂 1080p 内容持续至少十分钟，以及独立物理多机，均未完成验证。Qt 缩放、关闭单一来源、合成整屏和同机多进程只是替代覆盖。
- **正式旧媒体包对受保护窗口仍可能静默冻结。** 正式媒体包不识别明确的窗口保护标记；遇到受保护窗口时可能停在最后画面而不明确失败。显式保护标记修复只存在于未发布候选中，未进入正式包。
- **受限网络下仍有控制面失败观察。** 测试链路出口受限时，曾出现观看端 `RATE_LIMITED`、控制请求超时和单批次失败。按开发者指示网络优化暂缓，这些结果不构成网络性能通过，也不代表限制已被接受。
- **变化块仍是可选模式。** 变化块在八收和 1080p 长时场景对出口带宽更敏感，当前保留为可选无损模式，不作为默认编码或已通过的长时结论。
- **历史测试证据存在缺口。** 早期验收使用的测试 EXE 及其源码快照未全部保留；现有结论按保留宿主和逐批绑定路径成立，不能声称历史二进制可按原字节复现。

### 未发布候选

- 候选媒体包加入受保护窗口的明确失败路径（候选 SHA-256 `ba24e003…`，入口 `e9d9ae81…`），只在隔离场景和专项测试中验证；未发布、未替换正式包，也不继承正式包的完整长测与 P2 结论。
- 候选曾出现一次真实失败：关闭唯一来源后，发布端先报 `Service request timed out`，随后为 `Service lease unavailable`，卸载约 40 秒后返回 `unloadOk=false`。同一候选复跑和正式旧包同场景均正常，原因尚未确定，不能写成已修复；候选的来源关闭与媒体释放路径不能据此获得无保留通过。
- 候选没有版本或 API 变化。
