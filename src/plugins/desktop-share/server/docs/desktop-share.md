# 桌面共享服务端插件

## 功能简要说明

`desktop-share` Java 服务端插件（版本 `0.1.0`，服务端 API `0.2`）为桌面共享提供房间控制与媒体转发：客户端通过 TCP 控制连接建房／入房，通过 UDP 上传和接收媒体片段；服务端只按房间和流代次逐片转发，不重组、不解码、不重编码，也不保存视频历史、重传队列或关键帧缓存。

- 房间：共享者创建房间后得到八位十进制房号和每成员独立的媒体 token；观看者凭房号加入，最多八人。共享者停止、断线或超时后房间关闭并通知成员。房号只在生成它的服务端有效。
- 容量：默认最多八个房间、每房间一名共享者和八名观看者、整机 72 个桌面会话、160 Mbps 视频出口；每名观看者按当前档位码率 ×1.25 预留出口。控制请求默认每会话 20 次／秒、突发 20。
- 容量配置在插件启动时从 `plugins-data/桌面共享/config.json` 读取一次，只能降低、不能超过硬上限；文件或字段缺失使用默认值，非法配置阻止启动并给出字段级原因，修改后需重启。示例见 [config.example.json](config.example.json)。
- UDP 媒体：注册必须匹配会话、房间、token 和 TCP 对端 IP，首次注册固定来源端口；只转发当前共享者、当前房间、当前代次且来源端口匹配的片段。服务端不缓存待重发片段，`sendUdp` 失败只计数并丢弃。
- 控制流程覆盖握手、建房、入房、离开、停止、心跳和流配置／就绪／关键帧／反馈；准备、控制活动、UDP 注册和保活均有超时。关房原因包括共享者停止、断线、超时、媒体失败、准备超时和服务端停机。
- 日志只记录房间／会话内部 ID、档位、关闭原因、成员数和聚合计数，不记录 token、房号、完整控制消息或视频内容。

使用条件：

- Linux 服务端，运行 Java 25 宿主。把 `z2hub_desktop_share.jar` 放入服务端运行目录的 `plugins/`，重启宿主后加载；只支持启动时扫描。
- 服务端 API 必须匹配 `0.2`；客户端插件与服务端插件版本相互独立。
- 共享者与观看者必须连接同一服务端；服务入口应限制在 ZeroTier 或可信内网，房号不提供身份认证。客户端侧的功能与限制见[客户端插件文档](../../client/docs/desktop-share.md)。
- 不提供自动降档、自动重连、客户端直传回退、媒体重传队列或远程键鼠控制。

## 当前遗留问题

正式服务端插件为 `z2hub_desktop_share.jar`（版本 `0.1.0`，服务端 API `0.2`，SHA-256 `4790af26…`）。当前没有未发布的服务端候选或替代包。

- **阶段七仍未关闭。** 正式服务端插件自 P2 绑定后没有版本或行为变化，但端到端交付仍受客户端与媒体侧未关闭项约束，不能据此宣布阶段七完成。
- **独立物理多机未验证。** 现有真实运行均在单台 Windows 主机上以多个本地观看进程连接 Linux 服务端完成；不能代表多台物理观看主机、真实跨机网络或长时间多机性能。
- **容量与出口只在启动时配置。** 修改配置需重启；运行中不自动调整档位、不自动重连、不向客户端直传回退，也不保存媒体重传队列。这些是首期明确的范围边界，不是已经验收通过的能力。
- **客户端侧限制未被服务端消除。** RSS 未定位、原生 DPI／多屏／锁屏／权限、真实复杂 1080p、正式旧媒体包受保护窗口冻结、候选来源关闭后的释放失败，以及受限网络下的控制面观察，仍会直接影响端到端体验。服务端没有针对这些项的独立候选或关闭记录。
