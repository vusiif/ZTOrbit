# 媒体插件功能与当前遗留问题

## 功能简要说明

媒体工作进程 `media 2.0.0` 通过 `media.session / 1` 向业务插件提供屏幕／窗口／摄像头采集、H.264 与 `bgra-tiles` 编解码、视频预览和轨道生命周期；桌面共享只使用公开 Media API，不直接接触采集或编解码实现。媒体服务与 SDK 的完整契约见[媒体服务](media.md)、[自适应分块](tiles.md)和 [Windows 窗口采集](window-capture.md)。

## 当前遗留问题

媒体包文件名为 `z2_media_worker-v2.0.0.z2plugin`，新构建的 worker 入口为 `runtime/bin/z2_media_worker.exe`。本次产物更名不表示以下功能限制已解决。

### 正式包

- **受保护窗口可能静默冻结。** 正式媒体包不识别明确的 `WDA_MONITOR`／`WDA_EXCLUDEFROMCAPTURE` 标记；受保护窗口可能继续输出最后画面而不产生明确失败。只有未发布候选加入显式失败路径。
- **长时内存阶跃未定位。** 三十分钟桌面共享运行中客户端 RSS 在稳定窗口内有界，但此前出现过的约 +10.72 MiB 阶跃没有被独立复现，分配点未定位；同一运行中的媒体 worker RSS 只作为相关观察，也没有定位到分配点。不能据此称为无泄漏。
- **原生采集环境未验证。** 原生每显示器高 DPI、多屏拔插、锁屏／安全桌面、真实权限拒绝，以及真实复杂 1080p 内容持续至少十分钟，均未验证。Qt 缩放、合成整屏和关闭单一来源只是替代覆盖。
- **受保护／安全桌面边界未验证。** 在明确的窗口保护标记之外，锁屏、安全桌面、DRM 和其他捕获权限拒绝仍可能只表现为无新帧或冻结，不能识别为明确失败。
- **变化块仍受出口带宽约束。** `bgra-tiles` 为可选无损模式；八收和 1080p 长时场景对上行／出口更敏感，在受限链路下曾出现首帧超时或单观看端 `RATE_LIMITED`。它不作为默认编码或已通过的长时结论。

### 未发布候选

- 候选只在正式包基础上替换媒体 worker（完整重建还使 `flip` 扩展字节变化），修复受保护窗口的明确失败。专项测试与隔离 E2E 只在限定范围通过，未经过完整 P2、弱网矩阵或长时验收，不能代替正式包结论。
- 候选曾出现一次来源关闭后的释放／卸载失败：发布端报 `Service request timed out`，随后为 `Service lease unavailable`，卸载约 40 秒并返回 `unloadOk=false`；同一候选复跑和正式旧包同场景正常，原因未确定，不能写成已修复。
- 候选没有版本或 API 变化，也未进入 `build/dist/plugins/`。
