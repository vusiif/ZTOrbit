## 插件后台热加载

2026-10-15：客户端的包读取、认证校验、解密解压、运行库激活和业务 DLL 预加载改由独立线程池串行处理；运行库激活另用进程内互斥保护多个加载器。`package::inspect()` 对 v2 会完整认证所有文件，不能留在 GUI 线程。插件根 QObject 的实例化、菜单注册及生命周期钩子继续在 GUI 线程执行，`onCreate()` 返回的任务仍使用原初始化线程池。

宿主内部 `loadFile()` 成功只表示接收请求，最终就绪或失败通过 `loadFinished` 报告。加载目录立即发布 `loading` 状态，阻止重复请求；侧栏显示禁用的加载占位项，注册后菜单继续等待初始化成功。关闭时同时取消待加载包与初始化任务，异步等待后台线程及资源释放完成。公开 SDK、API 代际与根 VERSION 均不改变。

验证覆盖 64 MiB 资源包卸载后重新加载（请求耗时小于 100 ms，GUI 定时器持续响应）、加载前取消退出、失败清理与重复加载；Windows 原生 QML 点击验证加载时切换设置／主题、完成后进入插件菜单。现有语音包连续加载／卸载、页面创建与业务库真实卸载通过；需要远端服务器的录音回环／房间测试未运行。

## 中转站关联的部署假设

网络与 Moon 的关联按同一服务器部署设计：网络由该服务器的 ztncui 创建，Moon 由该服务器的 ZeroTier 创建并签名。这是关联机制的适用前提，不代表任意网络与 Moon 都存在对应关系；更换控制端或采用跨服务器部署时，需要重新确认此假设。

网络授权仍由控制端管理，分发中转站配置不替代授权。

## 发行包边界

正式发行包只包含主程序及运行依赖，测试辅助程序和测试数据不随包发布，避免模拟 CLI 被误当作真实服务工具。

Windows 主程序及当前 API SDK 分别压缩为 `dist/windows-x64.zip` 和 `dist/ZTGUI-api-v<API版本>.zip`。插件独立放在 `dist/plugins/`，正式入口是包含私有运行依赖和许可证的 `.ztplugin`，不进入主程序包。主程序只部署基础 Qt 与 libsodium；客户端导入包即可使用，构建目录中的裸 DLL 仅作诊断。

编译范围与脚本由 [ztgui-build](../.agent/skills/ztgui-build/SKILL.md) 管理，实现位于技能内 `scripts/`，仓库顶层脚本只转发调用。默认显式构建主程序目标；API 使用上次成功打包的内容指纹判断更新，记录在构建缓存中，应用补丁变化不触发 API 更新。SDK 更新采用干净安装目录；ZIP 丢失或损坏但 SDK 未变时仅重新压缩。插件构建必须由用户指定，语音入口参数为 `-BuildVoicePlugin`；主程序部署不读取业务 DLL；独立插件入口仅分析自己的目标。

Windows 打包在目标目录旁创建干净暂存目录，全部构建、Qt 部署、运行库和许可证复制成功后才替换发行目录。旧目录整体保留为同级 `<目录名>.previous-<随机编号>` 备份，已有日志、插件数据和自行添加的插件不会混入新发行包；需保留的数据可从备份中迁移。部署失败时保留原目录与未完成的暂存目录，替换失败时尝试恢复旧目录。输出路径不能是磁盘根目录、项目根目录或其祖先，也不能是链接目录。

## 悬浮框关闭动画

Qt 原生弹窗关闭路径依赖立即隐藏窗口并释放输入捕获；不能在 `closeEvent` 中忽略关闭，再等淡出动画结束才调用 `done()`。自定义对话框同步结束真实窗口，淡出交给不接收鼠标或焦点的短时快照，保证动画期间后续点击、键盘操作和模态流程能够继续。淡入使用窗口透明度，避免对整棵控件树逐帧执行透明度效果。

Windows 原生右键菜单选择后的关闭可能一并隐藏所属的 `Qt::Popup`。插件“关于”操作在菜单释放输入捕获后排队恢复插件列表并打开子浮窗，关闭子浮窗后保留列表；离屏测试不足以验证这一行为，需使用Windows原生窗口平台。

Qt 6.8 的活动弹窗鼠标分支不会自动生成右键菜单事件，因此插件列表直接处理右键松开，在事件处理结束后排队打开菜单；仍保留自定义菜单事件入口并避免重复弹出。测试须从窗口发送鼠标按下/松开事件，直接注入 `QContextMenuEvent` 会绕过这个故障路径。修复前的Windows窗口鼠标回归复现了菜单未出现，修复后的相同用例验证菜单与“关于”子浮窗能够打开。

macOS 的实机验证与正式分发要求见 [macOS 文档](macos.md)。
