# 维护约定

网络部署与默认连接行为统一遵循[网络约定](network-conventions.md)。前端模型与插件引擎寿命见 [QML 维护约定](qml.md)。本文保留跨平台维护约束和资源清理边界，常规功能变更见根 [CHANGELOG](../CHANGELOG.md)。

独立插件 API／服务、显式依赖调度与媒体进程隔离已在 Windows x64 实施；当前契约见 [插件服务](plugin-services.md)。媒体运行库仅在工作进程中加载；旧普通插件的非 Qt 私有库仍可能保留至进程退出。

## 版本管理

- 客户端程序版本读取根 `VERSION`，服务端程序版本读取根 `SERVER_VERSION`，两端独立发布。
- API 版本取对应程序版本的前两段数字和相同预发布后缀；程序补丁号不改变 API 版本。
- 版本文件由开发者指定，功能、构建、文档和修复任务不自行修改版本。
- 未分配新版本的变更写入 `CHANGELOG.md` 的未发布章节。
- 命名和迁移规则见[项目命名](naming.md)，本机 ZeroTier 配置规则见[本机配置](local-config.md)。

## 插件后台热加载

客户端的包读取、认证校验、解密解压、运行库激活和业务 DLL 预加载由独立线程池串行处理；运行库激活另用进程内互斥保护多个加载器。`package::inspect()` 对 v2 会完整认证所有文件，不能留在 GUI 线程。插件根 QObject 的实例化、菜单注册及生命周期钩子继续在 GUI 线程执行，`onCreate()` 返回的任务仍使用原初始化线程池。

宿主内部 `loadFile()` 成功只表示接收请求，最终就绪或失败通过 `loadFinished` 报告。加载目录立即发布 `loading` 状态，阻止重复请求；侧栏显示禁用的加载占位项，注册后菜单继续等待初始化成功。关闭时同时取消待加载包与初始化任务，异步等待后台线程及资源释放完成。

## 网络部署约定

服务器拓扑、网络 ID／ZTID／Moon ID 对应关系、服务端口、ztncui 的 `/24` 网段与服务器固定 `.1` 地址，以及支持范围，统一以[网络部署与默认连接约定](network-conventions.md)为准。其他部署设置由部署者自行负责。

## 网络成员查询与 Windows 端口预检

网络成员查询按[网络约定](network-conventions.md)定位服务器与控制器。客户端使用现有 `builtin/controller.members` 协议，展开时立即请求、随后每 5 秒轮询，慢请求不重叠；折叠、网络移除及页面析构取消请求。每轮成功取得成员后，对首个虚拟 IPv4 异步执行系统 ping（Windows 为 `ping -n 1 -w 4000 <ip>`），4 秒超时；同一成员不并发重复检测，结果返回前保留上轮文本，不回退到 peers 延迟。ICMP 不要求目标运行 ZTOrbit，但目标仍需允许 ICMP 回显。公开数据发送工具使用成员授权/IP 列表进行 UDP 18100 单播，广播也是逐成员发送；客户端业务插件负责监听和应用层可靠性。

Windows 启动、安装后启动及重启先检查 IPv4/IPv6 的 TCP/UDP excludedportrange；配置主端口冲突时，只停止 ZeroTier 服务，选择 20000–29999 中无保留且可绑定的端口，原子更新 local.conf 的 settings.primaryPort 并保留 `.zto-backup`。其他配置保留，无效 JSON 报错，不停止 WinNAT 或删除系统保留范围。服务达到 Running 后还验证从 zerotier-one.port 读取的本地 API。依据 [ZeroTier 客户端配置](https://docs.zerotier.com/config/) 和 [Windows netsh 接口](https://learn.microsoft.com/en-us/windows-server/administration/windows-commands/netsh-interface)。

网络成员备注沿用 QSettings 的 `names/peers/<小写 ZeroTier ID>`，不按网络分组，同一节点跨网络共享备注。默认显示成员 ID，服务器名称不覆盖本地备注；轮询按稳定 ID 保留成员行和编辑状态。

## 发行包边界

正式发行包只包含主程序及运行依赖，测试辅助程序和测试数据不随包发布，避免模拟 CLI 被误当作真实服务工具。自动更新使用独立的 `z2_updater.exe`（与 `Z2.exe` 同级，无 Qt 依赖），协议、配置与静态托管要求见[自动更新](auto-update.md)；本机状态重置的删除范围与失败处理见[重置 ZeroTier](reset-zerotier.md)。

Windows 主程序及当前 API SDK 分别压缩为 `build/dist/Z2-windows-x64.zip` 和 `build/dist/Z2-api-v<API版本>.zip`。插件独立放在 `build/dist/plugins/`，正式入口是包含私有运行依赖和许可证的 `.z2plugin`，不进入主程序包。主程序只部署基础 Qt 与 libsodium；客户端导入包即可使用，构建目录中的裸 DLL 仅作诊断。

编译范围与脚本由 [zto-build](../.agents/skills/zto-build/SKILL.md) 管理，实现位于技能内 `scripts/`，仓库顶层脚本只转发调用。默认显式构建主程序目标；API 使用上次成功打包的内容指纹判断更新，记录在构建缓存中，应用补丁变化不触发 API 更新。SDK 更新采用干净安装目录；ZIP 丢失或损坏但 SDK 未变时仅重新压缩。插件构建必须由用户指定，语音入口参数为 `-BuildVoicePlugin`；主程序部署不读取业务 DLL；独立插件入口仅分析自己的目标。

Windows 打包在目标目录旁创建干净暂存目录，全部构建、Qt 部署、运行库和许可证复制成功后才替换发行目录。成功验证后删除构建备份。已有日志、插件数据和自行添加的插件不混入新发行包。部署失败时保留原目录与未完成的暂存目录，替换失败时尝试恢复旧目录。输出路径不能是磁盘根目录、项目根目录或其祖先，也不能是链接目录。

## 插件清理、数据与迁移

中转登记和协议边界见[多中转通信](network-relays.md)。中转表／成员缓存仅后台线程访问，回调在宿主事件线程执行；停止时先取消工具请求和订阅，正在执行的回调（包含嵌套事件循环）退出前不释放 DLL。onDestroy 异常或卸载失败保留句柄与缓存到进程退出，不再次执行销毁。私有缓存使用进程锁，禁用锁文件的时间过期判定；仅清理已结束进程的专用目录。Windows 可能短暂保留 DLL 文件，卸载后清理重试最多5秒，未删除目录在下次启动恢复清理。

插件目录以客户端程序目录为基准；服务端插件、数据、日志以启动工作目录为基准。2026-10-18 起客户端运行数据统一由 `StorageContext` 选根：程序目录可写时使用程序目录，否则使用当前用户的 `AppLocalDataLocation/installations/<installKey>/profile`，并用 `route.json` 记住回退选择；回退后即使程序目录恢复可写也不自动迁回。宿主设置写入活动根的 `settings.ini`，不再读写默认注册表；旧 `ZeroTierGUI/ZTOrbit` 与 `ZeroTierGUI/ZeroTier GUI` 的 `appearance/`、`rendering/`、`names/`、`plugins/disabled`、`plugins/retain`、`window/qml/`、`tables/qml/` 白名单在首次迁移时按“目标 > 当前来源 > 历史来源”补缺，写入并校验后才清除来源键；迁移完成记录在 `.zto/settings-migration.json`，损坏 INI 保留原文件。读取完成标记、读取来源、写目标、删除来源键和写标记的全过程持有 `.zto/coord.lock`；锁被其他进程占用时返回未完成、保留全部来源键、不写完成标记，下次启动重试。宿主 INI 只有一个写入方 `SettingsStore`：QML 的 `window/qml`、`tables/qml` 通过 `backend.hostSetting()`／`setHostSetting()` 读写，不使用会在加载时写默认值的 QML `Settings` 元素。`StorageContext::settingsMigrationPending()` 为真（迁移记录损坏或 `settings` 项未结算）时，`SettingsStore` 拒绝全部持久写入且不创建目标文件，旧注册表导入也不写完成标记，避免新的目标文件让下次复制判定为“已存在”而永久丢掉原值；`settings` 以外的迁移项失败只限制对应插件数据。

个人根首次选定时会把共享根的 `settings.ini`、`plugins-data/*`、`.zto/plugins` 与 `.zto/settings-migration.json` 分项复制到个人 profile；活动租约、待删记录、日志和可丢弃缓存不复制。插件日志与 `id-*/cache/` 在 `plugin-data` 类别中按顶层目录排除（只复制持久设置、业务数据和归属），排除的文件数记录在迁移项的 `excluded`。进度写入 `.zto/migration.json`，以每个项的 `copied`／`existing`／`missing` 状态而不是 `profile.json` 是否存在决定后续启动是否重试：部分失败保留来源并在下次启动继续，目标已存在不覆盖，来源缺失标为 `missing`；记录损坏时保留原文件、本次不迁移并提示。`route.json` 只表示选定的个人根，迁移未完成时不会对外声称迁移成功。任一插件 `plugin-data` 项未恢复（`partial`／`failed`）或迁移记录不可读时，该插件数据目录的持久写入（`writeFile`／`updateFile` 的配置、业务文件）被明确拒绝并返回原因，仅 `cache/`、`logs/` 可继续写；`StorageContext::migrationComplete()` 暴露真实状态，避免插件初始化的默认值占据待恢复目标。

客户端插件数据按经过包校验的稳定 ID 归属到 `plugins-data/id-<小写 ID>/`，显示名只用于展示和历史迁移；语音配置在 `id-voice-chat/config.json`，备注在 `member-remarks.json`。旧显示名目录只在同一协调锁内、登记本进程租约之前检查该 ID 没有其他进程／实例租约时迁移；存在、无法读取或无法确认的租约都会保留旧目录并提示，租约释放后下次加载再迁移，不预创建空目标目录。自动迁移只接受位于 `plugins-data` 下的单一目录名：显示名本身不受字符集限制，但 `../`、绝对路径、分隔符或无法作为目录名的候选不会成为路径，重命名前还会复核来源规范化父目录与链接边界。插件扫描在任何实例启动前，用全部已认证安装包（含禁用、不兼容、未加载）登记 `.zto/plugins/<id>.json` 的显示名归属，并把同一份完整清单保留在内存中参与迁移决策；同名对应多个 ID、登记失败、相关所有权记录不可读或同一安装目录内存在无法认证的包时保留旧目录、不自动迁移，等归属可确认后再处理（只保留损坏记录本身不等于保护它应覆盖的旧目录）。每个进程在 `.zto/leases/` 持有 ID 级租约，删除时按租约保守判断。包导入与删除共用安装目录的 `.import.lock`，跨 profile 串行；需要数据根协调锁时固定先包锁、后 `.zto/coord.lock`。完整删除只接受通过认证的包：重新校验包、认证元信息、目录边界和 ID 归属，并先读取 `.zto/plugins/<id>.json`；记录不可读或 ID 不匹配时取消删除，记录缺失允许继续但先写删除墓碑。认证失败的包拒绝完整删除、不删数据也不报告“已安全删除”；只提供明确的“仅删除包文件、保留数据”入口，结果说明数据仍保留。已确认删除先原子写 `.zto/pending-deletions/<id>.json`（`dataRoot` 为真实插件数据根，另记授权时的包 SHA-256），再关闭旧配置导入墓碑、把包移入同卷受控待删区、删除当前 profile 数据、最后移除待删包；启动在插件扫描前按当前活动根恢复记录，恢复全程持有安装目录包锁，并在同一个数据根协调锁区间内重新认证当前安装清单（重装同 ID 包会保留其数据）、复查所有权记录与租约、写导入墓碑、移包和删数据；原包与待删包同时存在、路径越界或为链接、租约不明、记录根不匹配、包无法重新认证或包哈希与授权时不一致时保守保留并显示。宿主在 `.zto/plugins/<id>.json` 保存 ID、历史显示名、导入状态和删除墓碑，不保存业务配置。客户端、Java 服务端与归档 C++ 服务端的 SDK 版本相互独立，IID 与二进制不能混载；Java 服务端插件使用 `plugins/*.jar` 与 manifest `apiVersion`。网络数据接口只分发给本机同 ID 插件；客户端插件间的依赖另通过 ZTPK3 声明和通用服务租约管理，不能私自访问其他插件对象。插件扫描若发现无法解析或未通过认证的已安装包，会把相关 `id-*` 数据标记为归属不确定：无主扫描将其设为不可删除并显示原因，只有移除该包后才重新按可验证归属判断。

解压缓存使用活动根的 `cache/plugin-packages/<userKey>/<runId>/`，带 `owner.json`、会话锁和用户缓存索引；加载／卸载失败、正常退出（隐藏清理模式等待原进程退出）、崩溃后启动和程序搬移都通过索引与所有权令牌回收。索引只给候选位置，不授予任意路径删除权；`owner.json` 记录进程创建标识，会话根下的 `workers.json` 记录本会话 worker 的 PID 与创建标识（由 `ServiceBroker` 启停时登记／移除）。PID 只有在创建标识一致时才视为存活，PID 复用按已退出处理；正常退出的隐藏清理入口只接收用户键、运行 ID 和所有权令牌，并从用户缓存索引解析根路径，索引未登记、令牌不匹配或结构越界都拒绝。`prepareCacheSession` 在索引登记失败时直接报错，不继续解压；清理前还要确认残留 worker 已退出且目录内没有链接／junction，缺少 `workers.json` 的旧会话同样视为无法确认，任一不满足就保留目录和索引供下次启动重试，不递归删除无法验证的目录。归档服务端和打包工具仍显式使用自身临时缓存策略。

日志单文件 10 MiB 轮转，关闭的历史日志保留 30 天且每个归属最多 100 MiB；插件业务 `cache/` 按最后写入超过 7 天或每插件 256 MiB 淘汰，配置和备注不参与自动清理。总量淘汰按最后修改时间升序删除最旧文件；启动、每日维护、日志轮转和业务缓存写入后都会去抖触发同一后台调度器，同一时间只运行一个任务，自动任务不删除无主数据。设置页“存储”分区详情弹窗的占用统计、保留策略预览和无主数据分类在后台线程完成，GUI 线程只发起扫描并接收 `storageScanFinished`；扫描期间显示进行中状态，扫描与手动清理互斥，清理完成后重新扫描。详情弹窗显示实际路径、共享／个人模式、分类占用、待清理的日志／缓存项数与无主数据分类清单、最近自动维护结果、待完成删除事务及失败原因，并在确认前展示将删除的数量与字节数；未登记归属的旧显示名目录始终列为人工处理。插件 `cache/` 的读取在短时协调锁内取得该文件的活动锁，随后释放协调锁再读取，文件活动锁持有到读取结束；清理在协调锁内尝试同一活动锁，取得后删除，正在读取或仍被其他程序占用的文件按“在用跳过”报告，不强制删除也不计为已释放。只有 `cache/` 路径建立活动锁，其他业务文件的读取和长事务不受大缓存读取影响。

初始化只接受带取消令牌的 `onCreate()`，没有旧命名空间别名、入口优先级或旧接口回退。更新已有 SDK 安装目录时清理已废弃的公开头文件。旧应用名的 QSettings 迁移、CLI 定位和默认音频设备回退属于配置／平台行为，不能作为删除旧插件接口的附带改动移除。

可取消初始化在正常窗口关闭时异步等待；单次不可取消的第三方调用仍需等待返回，不能超时后释放其 DLL。长期业务使用独立的 PluginStopInterface 异步停止，完成后才销毁页面、工厂并执行最终清理。消费者停止失败保留其 DLL 和提供者；工作进程超时仅结束宿主拥有的进程树并等待退出。正常退出等待 shutdownFinished；直接析构只是紧急兜底，未完成停止的进程内 DLL 不会被强行卸载。

源目录迁移后不能沿用指向旧来源的 CMake 缓存；构建入口重新配置，成功验证后删除旧缓存备份。独立插件构建须明确选择安装后的 SDK，避免缓存选中仓库内部或旧 SDK。语音业务的协议、设备初始化耗时、部署与回滚由 [客户端项目文档](../src/plugins/voice-chat/client/docs/voice-chat.md) 和 [服务端项目文档](../src/plugins/voice-chat/server/docs/voice-chat.md) 维护。

## 原生平台与发行验证边界

Windows 托盘、标题栏、原生右键菜单及焦点／输入捕获行为需要 Windows 原生窗口平台验证；离屏测试不能替代。

正式 Windows 运行包若只部署 `qwindows`，强制 `offscreen` 会因缺少平台插件失败；曾发生的此类启动失败不属于单实例限制，不能记录为运行包启动成功。QML 原生关闭消息处理应使用预先缓存的窗口句柄，避免在原生事件处理期间调用 `winId()` 导致递归创建。

打包验证应在隔离副本执行：模拟 CLI、测试插件和日志不得进入正式包；清除开发 Qt 的 PATH、QML 导入路径等兜底，核对文件实际来自运行包／插件缓存。主程序和插件的发布文件应匹配对应构建产物，压缩包 CRC 与逐文件内容应匹配发行目录。源码或独立页面测试通过，不等于已有插件二进制已更新。

部署目录被占用时先保留旧数据和失败暂存，再解决占用并更新标准发行路径；临时换目录成功不代表标准目录已经更新。

macOS 的授权、签名和首次实机检查见 [平台文档](macos.md)。模拟安装脚本、只读查询及协议回归不能证明真实 ZeroTier 安装／卸载、首次 Moon 生成或系统授权已通过；多人听感、长时间语音和 macOS 的未验证项继续保留。
