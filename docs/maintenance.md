## 插件后台热加载

2026-10-15：客户端的包读取、认证校验、解密解压、运行库激活和业务 DLL 预加载改由独立线程池串行处理；运行库激活另用进程内互斥保护多个加载器。`package::inspect()` 对 v2 会完整认证所有文件，不能留在 GUI 线程。插件根 QObject 的实例化、菜单注册及生命周期钩子继续在 GUI 线程执行，`onCreate()` 返回的任务仍使用原初始化线程池。

宿主内部 `loadFile()` 成功只表示接收请求，最终就绪或失败通过 `loadFinished` 报告。加载目录立即发布 `loading` 状态，阻止重复请求；侧栏显示禁用的加载占位项，注册后菜单继续等待初始化成功。关闭时同时取消待加载包与初始化任务，异步等待后台线程及资源释放完成。公开 SDK、API 代际与根 VERSION 均不改变。

验证覆盖 64 MiB 资源包卸载后重新加载（请求耗时小于 100 ms，GUI 定时器持续响应）、加载前取消退出、失败清理与重复加载；Windows 原生 QML 点击验证加载时切换设置／主题、完成后进入插件菜单。现有语音包连续加载／卸载、页面创建与业务库真实卸载通过；需要远端服务器的录音回环／房间测试未运行。

## 中转站关联的部署假设

网络与 Moon 的关联按同一服务器部署设计：网络由该服务器的 ztncui 创建，Moon 由该服务器的 ZeroTier 创建并签名。这是关联机制的适用前提，不代表任意网络与 Moon 都存在对应关系；更换控制端或采用跨服务器部署时，需要重新确认此假设。

网络授权仍由控制端管理，分发中转站配置不替代授权。

## 网络成员查询与 Windows 端口预检

网络成员查询约定 IPv4 掩码 255.255.255.0，网络内 `.1` 节点监听 TCP 18100，并由该节点的本机 ZeroTier 控制器管理对应网络。客户端使用现有 `builtin/controller.members` 协议，展开时立即请求、随后每 5 秒轮询，慢请求不重叠；折叠、网络移除及页面析构取消请求。每轮成功取得成员后，对首个虚拟 IPv4 异步执行系统 ping（Windows 为 `ping -n 1 -w 4000 <ip>`），4 秒超时；同一成员不并发重复检测，结果返回前保留上轮文本，不回退到 peers 延迟。ICMP 不要求目标运行 ZTGUI，但目标仍需允许 ICMP 回显。外部控制器、不同服务器地址和非 /24 网络不属于此默认部署约定。公开数据发送工具使用成员授权/IP 列表进行 UDP 18100 单播，广播也是逐成员发送；客户端业务插件负责监听和应用层可靠性。

2026-10-15：成员 ICMP 专项与完整 GUI 回归通过（GUI 23 passed、2 个平台用例跳过），覆盖中英文 ping 输出、超时、取消、真实 Windows 回环 ping、5 秒轮询、新结果返回前保留成功／失败文本、重复刷新不重叠启动及折叠终止进程。Windows x64 Release 主程序及 ZIP 已更新，191 个文件逐一校验一致；版本保持 0.4.1，客户端 SDK 与 ZIP 复用，未编译业务插件。macOS 参数分支尚未实机验证。

Windows 启动、安装后启动及重启先检查 IPv4/IPv6 的 TCP/UDP excludedportrange；配置主端口冲突时，只停止 ZeroTier 服务，选择 20000–29999 中无保留且可绑定的端口，原子更新 local.conf 的 settings.primaryPort 并保留 `.ztgui-backup`。其他配置保留，无效 JSON 报错，不停止 WinNAT 或删除系统保留范围。服务达到 Running 后还验证从 zerotier-one.port 读取的本地 API。依据 [ZeroTier 客户端配置](https://docs.zerotier.com/config/) 和 [Windows netsh 接口](https://learn.microsoft.com/en-us/windows-server/administration/windows-commands/netsh-interface)。

网络成员备注沿用 QSettings 的 `names/peers/<小写 ZeroTier ID>`，不按网络分组，同一节点跨网络共享备注。默认显示成员 ID，服务器名称不覆盖本地备注；轮询按稳定 ID 保留成员行和编辑状态。

## 发行包边界

正式发行包只包含主程序及运行依赖，测试辅助程序和测试数据不随包发布，避免模拟 CLI 被误当作真实服务工具。

Windows 主程序及当前 API SDK 分别压缩为 `build/dist/windows-x64.zip` 和 `build/dist/ZTGUI-api-v<API版本>.zip`。插件独立放在 `build/dist/plugins/`，正式入口是包含私有运行依赖和许可证的 `.ztplugin`，不进入主程序包。主程序只部署基础 Qt 与 libsodium；客户端导入包即可使用，构建目录中的裸 DLL 仅作诊断。

编译范围与脚本由 [ztgui-build](../.agents/skills/ztgui-build/SKILL.md) 管理，实现位于技能内 `scripts/`，仓库顶层脚本只转发调用。默认显式构建主程序目标；API 使用上次成功打包的内容指纹判断更新，记录在构建缓存中，应用补丁变化不触发 API 更新。SDK 更新采用干净安装目录；ZIP 丢失或损坏但 SDK 未变时仅重新压缩。插件构建必须由用户指定，语音入口参数为 `-BuildVoicePlugin`；主程序部署不读取业务 DLL；独立插件入口仅分析自己的目标。

Windows 打包在目标目录旁创建干净暂存目录，全部构建、Qt 部署、运行库和许可证复制成功后才替换发行目录。旧目录整体保留为同级 `<目录名>.previous-<随机编号>` 备份，已有日志、插件数据和自行添加的插件不会混入新发行包；需保留的数据可从备份中迁移。部署失败时保留原目录与未完成的暂存目录，替换失败时尝试恢复旧目录。输出路径不能是磁盘根目录、项目根目录或其祖先，也不能是链接目录。

## 插件清理、数据与迁移

中转登记和协议边界见[多中转通信](network-relays.md)。中转表／成员缓存仅后台线程访问，回调在宿主事件线程执行；停止时先取消工具请求和订阅，正在执行的回调（包含嵌套事件循环）退出前不释放 DLL。onDestroy 异常或卸载失败保留句柄与缓存到进程退出，不再次执行销毁。私有缓存使用进程锁，禁用锁文件的时间过期判定；仅清理已结束进程的专用目录。Windows 可能短暂保留 DLL 文件，卸载后清理重试最多5秒，未删除目录在下次启动恢复清理。

插件目录以客户端程序目录为基准；服务端插件、数据、日志以启动工作目录为基准。文件服务使用 `plugins-data/<PluginInfo.name>/`，显示名改变会影响数据归属；客户端、Java 服务端与归档 C++ 服务端的 SDK 版本相互独立，IID 与二进制不能混载；Java 服务端插件使用 `plugins/*.jar` 与 manifest `apiVersion`。网络数据接口只分发给本机同 ID 插件；客户端插件间的依赖另通过 ZTPK3 声明和通用服务租约管理，不能私自访问其他插件对象。

初始化只接受带取消令牌的 `onCreate()`，没有旧命名空间别名、入口优先级或旧接口回退。更新已有 SDK 安装目录时清理已废弃的公开头文件。旧应用名的 QSettings 迁移、CLI 定位和默认音频设备回退属于配置／平台行为，不能作为删除旧插件接口的附带改动移除。

可取消初始化在正常窗口关闭时异步等待；单次不可取消的第三方调用仍需等待返回，不能超时后释放其 DLL。长期业务使用独立的 PluginStopInterface 异步停止，完成后才销毁页面、工厂并执行最终清理。消费者停止失败保留其 DLL 和提供者；工作进程超时仅结束宿主拥有的进程树并等待退出。正常退出等待 shutdownFinished；直接析构只是紧急兜底，未完成停止的进程内 DLL 不会被强行卸载。

源目录迁移后不能沿用指向旧来源的 CMake 缓存；构建入口保留旧缓存并重新配置。独立插件构建须明确选择安装后的 SDK，避免缓存选中仓库内部或旧 SDK。语音业务的协议、设备初始化耗时、部署与回滚由 [客户端项目文档](../src/plugins/voice-chat/client/docs/voice-chat.md) 和 [服务端项目文档](../src/plugins/voice-chat/server/docs/voice-chat.md) 维护。

## ZTServer Java 迁移（2026-10-17）

Linux 服务端从 C++17/Qt6 迁移为 Java 25 + Netty 4.2 + Maven，旧项目、旧测试和 C++ 语音插件归档到 `src/server-old/`（根 CMake 仅在 `ZTGUI_BUILD_SERVER_OLD=ON` 时构建）。新宿主保持 `ZTS1`、`builtin`、`ZTD1`、`ZTV1` 线协议，插件改为 Java JAR（`vusiif.ztgui.server.api`，API `0.2-beta`；迁移时为 `0.4`），安装/卸载/Moon 操作拆分为独立 `zt-installer.sh`。

验证范围与未验证项统一记录在[本轮迁移验证](validation/ztserver-java-2026-10-17/README.md)。该记录区分“本地/WSL 自动化通过”和“远端 Ubuntu 24.04 实机部署 + Ubuntu 22.04 容器”两类证据；旧 C++ 项目已在 WSL 构建宿主、测试与 C++ 语音插件（CTest 2/2），但旧版 Python Integration／Installer 测试未在本轮重跑；真实多人语音听感等未执行项必须保持标注，不能因 fat jar 能启动而推断全部平台已验证。
