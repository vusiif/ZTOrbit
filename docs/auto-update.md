# Z2 自动更新协议

更新服务器由用户在设置页点击“更新服务器”后填写 IPv4，端口默认 `18102`。IP 留空并保存即停用更新检查；没有内置地址或回退源。宿主只保存 `settings.ini` 的 `update/server`（例如 `http://10.10.10.1:18102`），不读取旧的清单 URL 配置。

界面只展示操作、进度和实际错误；协议与部署细节留在文档。服务器部署见[更新服务器](update-server.md)，监听范围见[网络部署约定](network-conventions.md)。

## 请求与响应

1. Z2 启动后检查一次，也可点击“检查更新”。请求 `GET http://<IP>:<端口>/updater`。
2. HTTP 200 的响应体是 UTF-8 JSON 更新清单；`X-Z2-Signature` 响应头是对**响应体原始字节**签名的 Ed25519 Base64 分离签名（解码后 64 字节）。客户端先验签，再解析清单；不另行请求 `.sig`。
3. 按当前平台、架构、SemVer 和最低可升级版本判断；相同或较旧版本不下载。
4. 需要更新时启动独立的 `z2_updater.exe --download ...`，由该进程请求清单里的 `/file?version=<版本>`。主程序不下载更新包，只接收进度并等待结果。
5. 下载程序校验大小及 SHA-256，成功后才提交 ZIP；主程序再校验并解压到独立暂存目录。随后以 `--plan` 启动同一更新程序并正常退出，助手等待退出后完成安装事务。

`GET /file` 会重定向到当前版本；客户端实际传递带版本参数的地址，避免检查后发布切换导致下载了其他版本。下载 URL 必须与配置的服务器同源、路径为 `/file`，其 `version` 参数必须等于选中的更新版本。

### 清单格式

```json
{
  "schemaVersion": 1,
  "channel": "stable",
  "publishedAt": "2026-11-05T00:00:00Z",
  "minUpdatableVersion": "0.5.3",
  "artifacts": [{
    "platform": "windows",
    "arch": "x64",
    "version": "0.5.3",
    "url": "http://10.10.10.1:18102/file?version=0.5.3",
    "size": 123456,
    "sha256": "<64 位小写十六进制>",
    "removeFiles": []
  }]
}
```

- `schemaVersion` 必须为 1；`artifacts` 为 1–64 项，同一平台/架构不得重复。
- `version`、`minUpdatableVersion` 使用 SemVer 2.0.0。只升级到严格更新版本，当前版本低于最低值时要求手动安装。构建元数据不参与比较。
- `channel`、`publishedAt` 可省略，出现时校验其类型；渠道字段不参与安装决策。
- `url` 必须是无凭据、无片段的 HTTP(S) URL。当前设置和部署使用内网 HTTP。
- `size` 为 1 到 512 MiB 的整数，`sha256` 必须为 64 位小写十六进制。
- 可选 `removeFiles` 是旧发行文件删除白名单，不允许指向宿主数据。

版本唯一来源仍是根 `VERSION`；本协议不自行分配版本号。发布包、应用、API 的版本规则见项目维护约定。

## 签名与网络边界

受信任公钥只来自构建参数 `ZTO_UPDATE_PUBLIC_KEY_BASE64`（Base64 编码的 32 字节 Ed25519 公钥）。它不能由设置或服务器更换。IP 未指定、公钥缺失或无效时不检查更新；保存服务器配置不立即发出请求。非法 IP/端口不覆盖已保存值，更新过程中禁止修改服务器。

`/updater` 清单上限 1 MiB，签名头上限 4 KiB；只接受支持的 JSON/二进制/纯文本响应类型。连接超时 10 秒、空闲超时 30 秒，最多 5 次重定向，禁止 HTTPS 降级到 HTTP。

下载助手为纯 Win32 C++17 程序，使用 WinHTTP 直接连接，不依赖 Qt 或系统代理。连接超时 10 秒，收发超时 30 秒，最多 5 次重定向且禁止 HTTPS 降级；仅接受 2xx 与 ZIP/二进制内容类型。它流式限制声明大小和 512 MiB 总上限，使用 BCrypt 计算 SHA-256，临时文件通过校验后原子提交。失败时删除自身临时文件并保留已有目标文件。

签名覆盖精确字节，不对 JSON 重新排序或序列化。上传普通发行 ZIP 后，在服务器执行 `bash ./update.sh --version <版本> --file <ZIP路径>`；脚本验证 PE 版本，使用服务器 root 专用私钥生成 `manifest.json` 和 `.sig`，并将签名作为 `X-Z2-Signature` 提供。现有公钥不变，私钥目录不对 Web 进程开放，发布者保留离线备份。

## 解压与安装

客户端收到的更新 ZIP 必须在根目录直接包含 `Z2.exe`、`z2_updater.exe` 和发行依赖。上传时可以直接使用带 `Z2-windows-x64/` 外目录的普通发行 ZIP，由服务器发布脚本自动转换，并拒绝运行数据、非法路径或不匹配的 PE 版本。

ZIP 只支持 STORED/DEFLATE，拒绝 ZIP64、分卷、加密、路径穿越、绝对路径、Windows 设备名、符号链接、重解析点、大小写重复及文件/目录冲突。逐条检查本地头、中央目录、CRC32 和解压大小；最多 4096 条目，单文件不超过 512 MiB，总解压不超过 1 GiB，并限制压缩比。只解压到活动存储根 `updates/staging/<id>/` 的新目录。

安装计划为严格 UTF-8 行式文件（`z2-update-plan=1`），记录安装/暂存/事务目录、父 PID、重启程序以及每个文件的 SHA-256、大小和相对路径。未知键、重复路径、非法值、尾部多余内容均拒绝。安装程序：

1. 等待主进程正常退出（默认最多 180 秒），不强制终止主进程。
2. 若将替换助手自身，先复制到 `updates/runtime/`，从副本继续。
3. 验证暂存文件，备份待替换或删除的旧文件，逐文件安装并复核。
4. 按删除白名单清理旧文件；成功后清理备份，写入结果并重启 Z2。
5. 失败时回滚，不自动重启。下次启动恢复中断事务；PID 与创建时间仍匹配的活跃助手事务不会被碰触。

`settings.ini`、`plugins/`、`plugins-data/`、`logs/`、`cache/`、`updates/`、`.zto/` 永不被发行文件替换或删除。路径遍历拒绝重解析点父目录。结果在 `updates/last-result.txt` 中读取一次，安装日志位于 `updates/log/updater.log`。

## 验证范围

自动回归使用临时安装树、回环 HTTP 服务和真实原生下载助手，覆盖签名、版本决策、下载失败保护、进程分工及安装事务；不会更新真实用户安装目录。内网服务器提供当前 `0.5.3` 的信息和发行文件；相同版本不触发安装，新的发行版本由开发者分配。真实 Windows 安装目录中的 UAC、升级和重启仍需人工验收。macOS/Linux 尚无安装事务助手。
