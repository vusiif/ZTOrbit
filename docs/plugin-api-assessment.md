# 常用插件能力评估（API 0.3）

当前 API 能承载语音聊天、桌面视频共享和文件传输插件。SDK 提供菜单、QQuickItem/QML 页面、初始化与清理钩子、配置读写和 ZeroTier 状态查询；插件可独立链接 Qt Network、Multimedia 或必要第三方库，自己实现协议和业务。评估依据是当前公开接口、宿主清理流程及语音插件实现；桌面共享和文件传输尚无对应插件或实机验证。

## 功能适配

| 功能 | 当前支持 | 插件负责的部分 | 实际限制 |
| --- | --- | --- | --- |
| 语音聊天 | 菜单/页面、异步设备准备、切换后页面保留、退出清理、配置和网络状态查询 | 音频设备、权限申请、Opus、房间、TCP/UDP、抖动缓冲、混音 | 已有独立语音插件及动态加载/音频测试；多人真实设备听感和 macOS 实机仍未验收 |
| 桌面视频共享 | 页面预览容器、初始化、菜单通知、配置保存及网络状态查询 | 屏幕/窗口选择、捕获、编码/解码、分辨率与帧率控制、拥塞控制、会话信令和网络传输 | 需要额外媒体库/后端及系统录屏授权，当前 SDK 没有统一封装 |
| 文件传输 | 文件选择页面、配置/任务状态保存、网络查询、插件自己的后台任务 | 用户选定文件的流式IO、协议、分块、哈希校验、进度、限速、暂停/恢复和断点续传 | `PluginFiles` 只有整文件读写，不能直接承担大文件流式传输；没有通用任务面板 |

Qt 的 [QScreenCapture](https://doc.qt.io/qt-6.8/qscreencapture.html) 和 [QWindowCapture](https://doc.qt.io/qt-6.8/qwindowcapture.html) 可作为捕获实现入口。Qt 6.8 的屏幕捕获依赖 FFmpeg 后端；具体平台的授权、可捕获目标和性能仍须单独验证。捕获能力不等于网络视频共享，实时编码和传输需要插件实现。

文件传输可通过 [QFile 的分块读写和 seek](https://doc.qt.io/qt-6.8/qfile.html) 以及 [QTcpSocket 的流式传输](https://doc.qt.io/qt-6.8/qtcpsocket.html) 实现；插件直接使用 Qt 的文件/网络接口无需依赖宿主内部头文件。大文件不能先全部读入 `QByteArray` 再调用 `writeFile`。外部文件由用户选择的路径访问；插件数据目录适合配置、任务元数据和小型缓存。

## 生命周期与资源归属

- `api::PluginLifecycleInterface::onCreate(util::HostServices&, const util::CancellationToken&)` 是唯一初始化入口。任务用于有限时间的准备工作，不能用作永久收包、录音或视频循环；宿主退出请求取消并在GUI事件循环中异步等待，不可取消的第三方调用等待正常返回。
- 长期运行的会话由插件根对象或其独立会话控制器持有，页面只显示状态并发送操作。当前语音插件的会话由页面持有，页面被缓存，所以普通菜单切换不会断开语音；页面销毁时同步停止会话线程。
- `onExitedTo()` 表示切换菜单，插件应自行决定暂停预览或继续通话/传输。不要默认将离开页面等同于终止会话。
- 页面拥有的线程、计时器和回调在页面析构时清理；根对象持有的后台资源在 `onDestroy()` 内同步停止。当前 `onDestroy()` 在页面和工厂释放后调用，不能再访问这些页面。

## 公共能力缺口与建议顺序

1. **长期业务的取消与停止。** 生命周期的唯一初始化入口带取消令牌和窗口异步退出，等待期间显示插件名称并保持GUI响应，排队的初始化跳过。仍缺少语音、视频和文件传输会话的独立异步停止阶段；页面析构及 `onDestroy()` 目前同步清理，内部单插件 `unload()` 也仍同步等待。后续可增加业务停止钩子，先禁止新业务、请求停止、等待完成，再销毁页面并最终调用 `onDestroy()`。取消不能中断不支持取消的第三方调用，不能超时后直接卸载仍执行中的DLL。
2. **公共任务状态及通知。** 会话控制器本身可以由插件实现；宿主若要在其他菜单显示来电、共享状态、传输进度，需增加任务注册、进度/失败通知及会话状态服务。现有菜单回调和文件保存不能替代这类服务。
3. **流式数据存储。** `readFile()` 使用 `readAll()`，`writeFile()` 接收完整 `QByteArray` 并原子替换；没有分块、追加、seek、列举、删除或元信息接口。可保留简易读写，再增加独立的流式文件接口或提供插件数据目录查询，让插件使用 `QFile`。后者是便利能力，不代表权限隔离。
4. **网络变化与设备发现。** Getter 是一次性JSON快照，没有缓存、变化订阅或应用服务发现。需要自动列出“支持语音/共享/传输的设备”时，可增加网络状态订阅和应用能力发现服务。ZeroTier 的 [peers 列表](https://docs.zerotier.com/faq/unknownpeers/) 表示本节点已知节点，包含基础设施，不能直接当在线联系人列表；[客户端CLI](https://docs.zerotier.com/cli/) 的 `listnetworks` 也是本节点加入的网络。插件仍需获取对方虚拟IP、端口及应用服务能力，例如用户填写地址或自有信令服务。
5. **身份与能力描述。** 目前按 `PluginInfo.name` 建立数据目录，符合命名目录需求，但名称变化、同名或文件系统大小写规则会影响数据归属。若后续需要改显示名称且保留数据，可将显示名与稳定存储键分开，并提供迁移约定。本次API结构与命名空间重构通过新IID排除旧插件，不保留旧接口或回退层；未来增加宿主服务时仍可使用能力查询描述可选业务能力。
6. **媒体权限与部署约定。** 插件可自行调用媒体库，但宿主的应用身份、权限提示、平台清单和随包部署仍会影响运行。当前macOS宿主已声明麦克风用途；桌面共享应单独验证录屏授权、媒体后端及签名后的运行行为。SDK无需把所有编解码器和平台捕获实现都变成公共接口，可提供一致的宿主权限/能力查询和部署约定。

这些缺口不会阻止插件自行实现三类功能。优先补充停止流程、任务通知及网络订阅，可以减少各插件重复实现的宿主集成逻辑；媒体引擎、传输协议和控制端继续由插件项目维护。
