# ZeroTier 网段 ping 与 TCP 中继观测（2026-10-21）

本次保持两端原始配置，不启用强制 TCP 中继、不修改路由、不重启服务。数据面探测全部使用 `10.10.10.0/24` 中的地址，且 `ping -S` 显式绑定对应 ZeroTier IPv4 源地址。远端脚本通过 Astral SSH 下发；管理连接不作为 ping 结果，也不计入 ZeroTier 服务进程的 TCP 中继连接。

## 结论

- `.3 → .201`、`.201 → .3`、`.3 → .1`、`.201 → .1` 均为 6/6 有效 ICMP 回显。
- 约 90 秒观测窗口内，两端均未观察到 ZeroTier TCP 中继活动；不代表未来不会触发自动回退。
- `.201` 的 API 全程报告 `tcpFallbackActive=false`；本机 `.3` 的 API 访问受权限限制，改用服务进程全部 TCP 连接快照，未发现任何非回环 TCP 连接。回环控制连接不属于 TCP 中继。
- `.201` 的首选路径记录显示，到 `.3` 使用 `10.126.126.2/9993`（Astral 网段）承载 ZeroTier UDP，到 Moon 使用 `124.221.198.141/9993`。所以“ping 的虚拟源/目标都是 10.10.10.x”与“底层路径经过 Astral”可以同时成立。
- 多个其他成员没有有效 ICMP 回显，完整失败记录保留；仅凭这些结果不能确定成员离线、ICMP 被阻挡还是链路未建立。

## 测试范围与方法

- 网络 ID：`5a3f1c454238ae4a`；目标来自 ZTServer `builtin/controller.members` 返回的 14 个已授权 IPv4 成员，没有扫描其余未分配地址。
- 源地址：`10.10.10.3`、`10.10.10.201`；各自排除本机后测试 13 个目标。
- 每个源分别在第 0、30、60 秒启动一轮；每轮每目标 2 次回显请求，超时 1200 ms，最多 4 个并行 ping 进程。
- 共 26 个源/目标组合、156 次回显请求；成功统计只计包含 TTL 和 RTT 的有效回显，不把“目标不可达”或“TTL 超限”计作成功。
- 约每秒采样一次 ZeroTier 服务进程 TCP 连接，远端同时读取 `/status`。实际间隔受命令开销影响，详见下表和原始时间戳。未做逐包抓包；若将来观测到 `tcpFallbackActive=true`，仅凭这个全局状态不能断言每一个 ping 都经过了 TCP 中继。
