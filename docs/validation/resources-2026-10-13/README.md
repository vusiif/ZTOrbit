# 资源占用分析

> 历史测量：本文数据采集于 2026-10-13 的应用 0.3.2 与旧媒体模型（主程序内 Multimedia／FFmpeg、裸语音 DLL）。它不代表当前客户端 0.5.1-alpha 的插件与媒体 worker 行为；当前打包边界见[插件服务](../../plugin-services.md)与构建技能。

2026-10-13，Windows 11 x64、Qt 6.8.3、AMD Radeon 760M，使用Release生产程序和干净解压的运行包。每种场景运行2次，启动后6秒取样，收起到托盘后1.5秒再取样，表中为中位数。相邻的模拟CLI通过独立PATH和查询日志验证确实被调用；不会安装、卸载、加入或退出真实ZeroTier网络。

私有提交是进程独占的已提交虚拟内存，工作集是当时驻留的物理页，包含共享DLL等；两者不能混用，也不代表显卡的专用显存。驱动、DPI、字体和数据量会改变结果。本次数字是受控样本，不是所有机器的保证。原始摘要见 [测量数据](resource-measurements.json)；复测脚本为 `src/tests/ProfileResources.ps1`，仅应对隔离的运行包副本执行，脚本会加入测试CLI及日志。该脚本仍是 0.3.2 裸 DLL／主程序内多媒体流程，不能复现 0.4.1 的 `.ztplugin` 与媒体 worker 场景。

## 磁盘

| 指标 | 优化前 | 优化后 | 减少 |
| --- | ---: | ---: | ---: |
| 运行文件总大小 | 115.76 MiB | 76.31 MiB | 34.1% |
| ZIP大小 | 48.19 MiB | 33.48 MiB | 30.5% |
| 包内文件数 | 1405 | 207 | 1198个 |

约19.68 MiB来自未使用的Mesa OpenGL软件库；其他收益来自多套控件样式／素材、多语言Qt翻译和QML调试插件。宿主已固定使用Basic，默认保留英文、简体中文和繁体中文Qt翻译。当时（0.3.2）还保留D3D编译器、Widgets原生托盘后备、音频、Multimedia及FFmpeg；0.4.1 起主程序发行包不再包含 Multimedia／FFmpeg，媒体依赖随独立 worker 包交付。SDK及应用版本保持原值，语音DLL未重编（当时为裸 DLL）。

Windows的D3D11和Qt的CPU场景图均不需要 `opengl32sw.dll`。需要显式OpenGL软件渲染兼容环境时用 `-IncludeOpenGLSoftware` 打包；第三方QML插件明确导入其他Controls样式时用 `-KeepAllQmlStyles`。插件自己的其他QML／图形／编解码依赖仍应按其要求部署。

## 内存

下表为私有提交，单位MiB；“少量数据”为2个网络、4个peer，“大表”为40个网络、35个peer。语音场景（当时）只加载并初始化现有裸DLL，没有入房或录音。

| 场景 | 优化前GPU | 优化后GPU | 优化后低内存模式 |
| --- | ---: | ---: | ---: |
| 空列表，显示窗口 | 102.97 | 96.00 | 55.86 |
| 少量数据，显示窗口 | 107.31 | 102.84 | 56.82 |
| 少量数据，托盘驻留 | 112.88 | 86.91 | 63.16 |
| 大表，显示窗口 | 140.62 | 115.34 | 68.96 |
| 大表，托盘驻留 | 146.06 | 98.10 | 75.28 |

少量数据正常窗口的工作集分别为154.82、146.33、110.93 MiB；大表分别为184.56、159.78、122.96 MiB。当时语音预初始化增加约20 MiB私有提交，其设备查询、线程准备和FFmpeg依赖保留在宿主进程；0.4.1 的媒体 worker 独立运行，不能按本表对比。

主要实现：启动时不创建14个关闭的弹窗／文件选择器；每行的菜单及备注编辑器按需创建，结束编辑后释放编辑器；成员子模型延迟分配；隐藏窗口时释放可重建的场景图、交换链、纹理等资源。恢复窗口会重新构建图形资源，因此更重视驻留内存而非保持渲染缓存。列表、展开状态、输入和语音会话继续保留。Qt运行时、字体和渲染驱动仍占据固定基础内存。

资源释放采用Qt公开的场景图／图形资源持久化设置，说明见 [QQuickWindow资源管理](https://doc.qt.io/qt-6.8/qquickwindow.html#resource-management)；静态Basic导入的依据见 [Qt控件样式选择](https://doc.qt.io/qt-6.8/qtquickcontrols-styles.html#compile-time-style-selection)。

设置中的“禁止GPU加速”默认开启，使用CPU绘制；保留已有显式选择，首次切换弹窗提醒完全退出、重新启动后生效。也可仅对本次启动强制禁用GPU加速：

```powershell
.\ZTGUI.exe --disable-gpu-acceleration
```

须先通过退出操作结束已有进程；标题栏关闭只收起到托盘，第二次启动会激活旧进程，不能切换渲染器。启动参数不改写保存的设置，使用该参数时界面开关显示开启且不可修改。CPU绘制适合当前以文本、表格和基本控件为主的管理界面。复杂动画、视频或自定义Shader插件需要另行评估，依赖GPU的插件需在设置中启用GPU加速。本次没有测量滚动帧率或CPU峰值，不能据此声称软件模式更快。

## 后台待机

窗口收起到托盘或最小化时暂停界面和服务状态轮询，停止成员刷新定时器，并取消在途 CLI 查询、成员查询及 ICMP ping。保留上次数据、备注和展开状态；恢复窗口时立即重新查询，继续正常轮询。已经发起的安装／服务操作继续完成。

插件网络服务不再随主窗口启动。发送请求、查询中转和接收订阅通过宿主管理使用期；首次使用等待本机 ID 与网络快照，最后一个在途请求结束或有效订阅取消后，停止轮询并释放工作线程、套接字、中转维护和探测资源。网络配置不变时不会重复提交给工作线程。窗口隐藏不取消持续订阅，语音连接、音频及必要心跳也继续运行。

优化的验收依据是隐藏／最小化后的零新增 CLI 查询、无周期服务状态更新、恢复后的及时刷新，以及订阅收发和取消后的资源释放。实际 CPU 降幅随插件和机器变化，未将这些行为验证换算成固定百分比。

## 验证

六组回归全部通过；精简运行包在清除本机Qt SDK导入路径后，完成原生Windows的菜单、编辑保存／取消、重复打开弹窗、指南、托盘恢复及语音手动连接验证。发布ZIP完成CRC及逐文件哈希校验，API SDK复用原包，当时应用版本为0.3.2。软件模式在生产程序的查询日志和Qt场景图日志中确认启用。

本次没有清理开发工具、历史备份和构建缓存；运行包体积与整个工作区体积是不同范围。未做列表虚拟化或延迟插件生命周期初始化，后续如处理数百／数千行数据或更多插件，可继续评估这些方向。
